## Overview

Xiaomi HyperOS/MIUI libxposed API 102 module. Settings UI: Jetpack Compose + Miuix. Hooks the processes in `app/src/main/resources/META-INF/xposed/scope.list`.

## Toolchain

- `compileSdk` 37 / `targetSdk` 37 / `minSdk` 35; Java 25. AGP `9.3.0`; Kotlin Compose `2.4.10`.
- libxposed API+service `102.0.0`; Miuix `0.9.3`; DexKit `2.2.0`. Native: `arm64-v8a` only.

## Layout

Sources under `app/src/main/kotlin/com/takekazex/hypertweak/`: `hook/` entry+hooks (`hook/base/` shared infra, `hook/rules/*` per-feature); `ui/page|effect|liquid|navigation|theme` Compose; `util/` utilities; JVM tests `app/src/test/`.

## Key Components

`HookEntry` per-process init; `Preferences` runtime prefs + cross-process sync; `XposedServiceManager` service boundary; `BaseHooker` lifecycle/resolution; `DexKitManager` obfuscated-class resolution (cached). Hook handles / hot-reload state belong to the lifecycle layer; runtime pref changes flow through `Preferences`, never UI-only state.

## Lockscreen Fingerprint Avoid

Settings → Experimental → Lockscreen Fingerprint Avoid (`KEY_LOCKSCREEN_FINGERPRINT_AVOID`, `KeyguardFingerprintAvoidHooker`). Modes 0 follow system, 1 no avoidance, 2 always avoid. OS4-only (UI gated `PlatformLevel.isOs4`); needs SystemUI restart; flows through `TWEAK_RESTART_SCOPES`. One of the few Int-typed (selector) tweaks: `markTweakedInt`/`currentTweakValueInt` store an Int baseline in the `tweak_baseline_` slot, and `clearRestartedScopes` writes that slot as Int — mixing a Boolean baseline in would crash the next `getInt`.

Mechanism: `KeyguardPanelViewController.nsslLockYPosition` is a `StateFlow<Triple<Int,Int,Int>>` combining 7 flows; the hook intercepts its inlined-combine lambda (3-arg `invoke` bridge) to force `Object[]` indices 5 (fingerprint-apply) and 6 (enrolled) for that one computation. `fingerApplyForKeyguard` is **not** replaced as a flow (it also drives fingerprint-icon visibility and the low-position area). Resolve the lambda class by **exact dex name**, not `getDeclaredClasses()` (R8 folds the `lazy{}` lambda into `$$ExternalSyntheticLambda6`). See docs for the 7-flow composition and verified values.

## Lockscreen Charging Detail (锁屏充电详情)

Settings → Experimental → Charging Detail Options (`KEY_LOCKSCREEN_CHARGING_DETAIL`, `LockscreenChargingDetailHooker`, OS4-only in UI). Master + options in second-level `ChargingDetailPage`, which keeps its own state (absent from `TWEAK_RESTART_SCOPES`; offers an in-page "Restart SystemUI" row). See docs for the source/broadcast details and the base-message WeakHashMap rule.

## Lockscreen Notification Per-Channel (锁屏通知 按渠道)

Settings → Tweaks → 锁屏显示所有通知 (`KEY_LOCKSCREEN_ALL_NOTIFICATIONS`, `LockscreenAllNotificationsHooker` in SystemUI + `ChannelKeyguardToggleHooker` in Settings, OS4 target). The two hooks share one switch: with it on, every notification shows on the keyguard by default **and** the per-channel 锁屏通知 switch is honored — a channel only stays hidden when its own switch is turned off.

Root cause (OS4 CN, `Settings-OS4.0.0.21.XPMCNXM` / `SystemUI-OS4.0.0.21.XPMCNXM`): MIUI's `NotificationSettingsManager.canShowOnKeyguard(Context,pkg,channel)` (`:512`) uses `USE_WHITE_LISTS = !IS_INTERNATIONAL_BUILD` on CN, so a real channel with no explicit key falls back to the system whitelist (`mAllowKeyguardPackages.contains(pkg)`) — most third-party channels are hidden even when the app switch is on (the switch only writes the package key). Meanwhile `ChannelNotificationSettings.removeDefaultPrefs()` (`:75`) hides the `allow_keyguard` checkbox and `mAllowKeyguard` is never assigned in that page (`updateDependents():296`), so per-channel 锁屏通知 can't be set at all.

Fix: `LockscreenAllNotificationsHooker` overrides `canShowOnKeyguard` with per-channel semantics — package key `false` hides the app; a channel key (`<pkg>_<channel>_keyguard`) is honored; no key → default show (bypasses the CN whitelist). It reads `app_notification` prefs live via `getSharedPreferences`, so no restart per toggle. `ChannelKeyguardToggleHooker` re-adds the `allow_keyguard` CheckBoxPreference after `removeDefaultPrefs` (captures it before, `setPrefVisible(pref,true)` after), assigns `mAllowKeyguard`, and binds an `OnPreferenceChangeListener` (a Java `Proxy` over `androidx.preference.Preference$OnPreferenceChangeListener`, since androidx isn't on the module classpath) that calls `NotificationSettingsHelper.setShowKeyguard(ctx, pkg, channelId, value)` → the per-channel key. Both hooks are gated on the master switch; SystemUI restart + Settings process restart required.

Verified 2026-09-01 (v283): compiled, unit tests green, `assembleRelease` green, R8 kept the reflection constants, and after `adb install -r` + force-stop both processes the LSPosed/`HyperTweak` logs showed `LockscreenAllNotificationsHooker: HOOK_OK ... canShowOnKeyguard(Context,String,String)` (SystemUI) and `ChannelKeyguardToggleHooker: HOOK_OK ... ChannelNotificationSettings#removeDefaultPrefs()` (both `com.android.settings` and `:remote`). On-device functional testing (open IT之家 channel page, per-channel 锁屏通知 toggle appears and sticks) is left to the user.

**R8 release rule (do not revert)**: `IconTunerFlows` builds its host class FQNs at runtime (`hostClassName(pkg, simple)`, StringBuilder — R8 can't fold non-constant fragments) and `proguard-rules.pro` keeps `kotlinx.coroutines.flow.**` + `kotlin.Pair` unobfuscated; **test the release variant on device** whenever a hooker reflectively touches bundled-library classes by name. (2026-08-21: release R8 obfuscated the bundled kotlinx, producing CNFE `z12` on every getter.)

**Stacked-signal regression rails (do not reintroduce)**: never pass internal `0x7e...` ids to `ImageView.setImageResource` (resolved below the hooked `Resources` API → `Resources.NotFoundException`, leaving the stock icon); never write fake ids into the views' `tag` (the theme-change collector re-applies from `View.getTag()` via `setImageResource`; a fake id throws inside the binder collector, killing its scope and freezing every flow-driven cellular feature); `idRes()` must resolve `com.android.systemui` ids from the host view's resources (never the module context); `icon_stacked_scale` is a direct 0.5–1.5 factor (do not ×0.1). See docs for per-slice targets and the 2026-08-21 diagnosis.

### Icon Left Placement (图标左置)

Settings → Experimental → Icon Tuner → 图标左置 (`LeftContainerHooker`, keys `icon_left_*`, OS4 targets; live on/off, no SystemUI restart). Shows selected status-bar slots in a LinearLayout after the home-screen clock in `R.id.phone_status_bar_left_container`. Uses **block-hide + self-rendered clones** (never moves a system view; a second `DarkIconManager` can't be built on OS4).
**Threading / hot reload (regression)**: `onPrepareHotReload` runs on the LSPosed binder thread and must NEVER touch views. v3 sets a `resetPending` flag only; the main-thread ticker does the teardown (v2 relocated actual views, throwing `CalledFromWrongThreadException`).
**Vertical centering (2026-08-23)**: the container's `gravity` must be `CENTER_VERTICAL` **and** `copy.gravity = CENTER_VERTICAL` on every cloned layoutParams (per-child gravity overrides container gravity); do not switch clone height to MATCH_PARENT (the source box is genuinely 20dp, manually centered). Master `icon_left_container_enabled`; each slot its own boolean key.

## AOSP Back Gesture

Vendored from `wxxsfxyzm/MiuiBackGestureHook` (Apache-2.0) through upstream commit `a5f1ae5...` (v0.8.5); reference clone at `/Users/ink/developer/refrences/MiuiBackGestureHook`. Upstream's hook ownership chain copied under `hook/rules/backgesture/`; `BackGestureHookRuntime` is a HyperTweak-only composition shim. HyperTweak-local changes are marked `HyperTweak:` and confined to `HookRuntimeCore.java`, `HotReloadHookRuntime.java`, and `MiuiHomeReturnHome*.java`. Preferences resolve through `Preferences`.

**Cross-cutting rails**:
- `ContextualSearchSystemHooker` must not clear its uid cache or PackageManager on hot reload (`systemPackageManager` was seeded once at early boot); `resolvePackageManager()` falls back to `ActivityThread.currentApplication()`.
- The system-server takeover bridge from commit `6192c2a` is **reverted** — do not restore it without a mechanism that doesn't lie to Launcher about ownership.
- Predictive return-home needs the module to drive the launcher home itself after commit (the module pilfers the pointer stream, so `NavStubView` never gets the UP that normally issues `CLOSE_TO_HOME`, `NavStubView.java:4597`). Launcher hooks split: `installMiuiHomeInputArbitrationOnly` always installs (no accepted-input token → SystemUI never starts a gesture); only the predictive half (`recents.anim.*` + driven `performAppToHome`) is gated by `KEY_AOSP_BACK_MIUI_HOME_HOOKS` + `LauncherVersion`.
- A driven return-home session is **handed off, not tracked**; `ReturnHomeSession.retention` is bounded by `STALE_RETURN_HOME_PREVIEW_TIMEOUT_MS` (a preview owner older than that is cancelled/finished) to avoid the launcher-stuck-blurred leak.
- Launcher 8 has `android:hasCode="false"` (no dex), so the predictive route only resolves on Launcher 7 and older; `LauncherVersion` detects this and the route defaults off when unsupported. Device baseline = Launcher 7.x.
- No separate haptic feedback; action selections read at dispatch; Direct Gemini/ChatGPT bare-launch actions were removed (ids 3/4 degrade to `DISABLED`). Feature defaults off; needs a SystemUI restart after setting changes and one reboot after install.

`CrossTaskWallpaperRuntime` (HyperTweak-only) draws the wallpaper behind the cross-task back animation when `KEY_CROSS_TASK_WALLPAPER_BACKGROUND` is on (upstream's `tintCrossTaskBackground` yields when it's on). `ImmediateMonetRefreshHooker` repairs HyperOS dropping AOD-marked wallpaper colors, forwarding both listeners through the original `handleWallpaperColors` path (defaults on, no SystemUI restart). See docs for the arbitration/token model and the Arrow-MasterLive/full detail.

## Power Button Long Press (长按电源键操作)

Settings → Tweaks → Navigation Bar → Power Button Long Press (`KEY_POWER_BUTTON_ACTION`, `hook/rules/system/PowerButtonCtsHooker.kt`). Re-binds long-press power: `DISABLED` (0), `CIRCLE_TO_SEARCH` (1), `DEFAULT_ASSISTANT` (2). `KEY_POWER_BUTTON_HAPTIC` (default on) plays the platform haptic when the action fires. Legacy `KEY_POWER_BUTTON_CTS` is superseded. On OS4 the binding lives on two stacked system_server layers: `PowerKeyRule#onMiuiLongPress(Object, long)` (MIUI 快捷手势) and `PhoneWindowManager#powerLongPress(long)` (AOSP fallback). The hooker intercepts both before dispatch (marks power key handled, runs the action, haptic only when it fired).

**Signatures (verify against the versioned jars, not the older `framework-services-2e880646` cache)**: `PowerKeyRule#onMiuiLongPress(Object, long)` (cache shows `(long)`; the release grew a first `Object` param — resolve by name + trailing long so both shapes match); `IContextualSearchManager.startContextualSearch(int, ContextualSearchConfig)` (AIDL grew a `ContextualSearchConfig` param; cache shows `(int)` — pass `null`). The default-assistant action routes through the platform assist pipeline (`SearchManager.launchAssist`), deliberately **not** the MIUI `launchAssistAction(String, Bundle)` overload. Actions/haptic read live at dispatch; enabling from disabled needs a reboot (system-server hooks).

## AOSP Restore

Settings → AOSP Restore (`ui/page/AospRestorePage.kt`, `Route.AospRestore`) — switches that hand a HyperOS component back to AOSP. Page keeps its own state, so keys are absent from `TWEAK_RESTART_SCOPES` and each summary states its own restart requirement.
- `AospPackageInstallerHooker` — forces `isCTS()` true for three methods (the AOSP installer is selected when `isCTS()`); **this deliberately relaxes MIUI install verification** (defaults off). Scoped to the calling thread via a re-entrant `ThreadLocal` depth counter (upstream uses a process-wide boolean). `BaseHooker.deoptimize(Executable)` is the shared helper.
- `AospSystemUiPluginBlockHooker` — hides the AOSP power-menu/volume plugins from SystemUI's own plugin framework via `PluginActionManager.loadPluginComponent(ComponentName)` (the single funnel); needs no root, fully reverted by turning off + SystemUI restart. Matching is by class name, not package.
- `AospVolumeHapticHooker` (`KEY_AOSP_VOLUME_HAPTIC_MIUI`, default on, greyed until AOSP panel master on; SystemUI restart) — the AOSP Compose volume panel ignores the `onPerformHapticFeedback` haptic intent and instead buzzes via MSDL's `SliderHapticFeedbackProvider.onProgress` → `DRAG_INDICATOR_CONTINUOUS` (a single key press animates the handle over ~250 ms, firing `onProgress` ~29×). Three hooks on unobfuscated names: play `miui.util.HapticFeedbackUtil.performHapticFeedback(MESH_NORMAL,false)` in `VolumeDialogControllerImpl$C#onPerformHapticFeedback(int)` (once per real volume step, skip at max/min), short-circuit `SliderHapticFeedbackProvider#onProgress(float)` (resetting the `hasVibratedAt*Bookend` fields) to kill the animation buzz, and route the bookend `MSDLPlayerImpl#playToken(DRAG_THRESHOLD_INDICATOR_LIMIT)` → `FLAG_MIUI_HAPTIC_MESH_HEAVY` at max/min (matching the stock MIUI panel's "top" cue). `HapticFeedbackUtil` is resolved reflectively with `ActivityThread.currentApplication()`. See docs for the verified flow.
- `ExtendUnlockHooker` — repairs Extend Unlock (formerly Smart Lock, from HyperTrust). Xiaomi does **not** modify `getUserHasTrust(int)`; the bug is the `mUserHasTrust` cache going stale. The after-hook re-derives trust only when neither `isSimPinSecure()` nor `isUnlockingWithBiometricAllowed(true)` explains the false result; it deliberately does **not** write back into `mUserHasTrust` (a race AOSP asserts against). Defaults off, needs a SystemUI restart. **The keyguard fix alone does nothing on a stock HyperOS device** — `dumpsys trust` shows the Extend Unlock agent disabled in the list; `syncTrustAgent` enables it (only that one component, removed again when the setting turns off). The manifest must `<uses-permission>` its own `RESTART_SCOPE` permission (receivers register with it as `broadcastPermission`, the *sender* holds it).
- `UnlockClipboardHooker` — restores AOSP's clipboard overlay editor by adding the app owning the current clip to `sCtsTestPkgList` (static-final; OS4 ART rejects reflective writes → `util/StaticFieldWriter.kt` Unsafe fallback; the `sun.misc.Unsafe` shim dropped `staticFieldBase`/`staticFieldOffset`, so it reads the shim's `theInternalUnsafe`). On OS4 `StaticFieldWriter` uses the platform `jdk.internal.misc.Unsafe`.
- `AospAppInfoEntryHooker` / `AospAppManagerEntryHooker` — add Settings SPA route entries to Security Center's app details / app manager. `AospAppManagerEntryHooker` hooks `onOptionsMenuViewAdded`, which **has an empty body** on this baseline (`AppCompatActivity:444`), so it deoptimizes the caller `AppCompatActivity$Callback.onPanelViewAdded` (resolved by signature). Both target `com.android.settings/.spa.SpaActivity` (exported=false), reachable because both run under `android.uid.system`.

## AOSP IME Navigation Bar (AOSP 输入法导航栏)

Restores AOSP's full-screen IME navigation bar for selected input methods, ported from Howard20181's Mi_AOSP_IME (GPL-3.0). Three places.
- `AospImeHooker` (keyboard process): flips `IS_INTERNATIONAL_BUILD` via `StaticFieldWriter` before `InputMethodService.hideImeRenderGesturalNavButtons` (do NOT short-circuit the return value — that bypasses `canImeRenderGesturalNavButtons()`); "MIUI-customized" is decided by `InputMethodServiceInjector.isImeSupport(Context)` first (the `MiuiCustomizedImePackages` snapshot is only a secondary fallback). The nav-bar controller is version-shaped (`NavigationBarController$Impl` on .15 vs `NavigationBarController` on .19). The caption inset is forced at `InsetsController.setImeCaptionBarInsetsHeight(int)` (a lone `getImeCaptionBarHeight` getter hook never fires on .19 — AOT-inlined).
- **Bar height = hard 48dp** (the framework dimen `input_method_navigation_bar_height` resolves to 20dp on .19, so the bar is "太矮"); the module pins the caption-bar insets, frame height and keyboard raise all to 48dp. Keyboard raise pads `InputMethodService.mInputView` (not the transparent `parentPanel` root), difference-based (`desired = clamp(...)`), evaluated continuously via an `OnLayoutChangeListener`; style-gated on `aospRaiseActive = aospBarActive && raiseStyle == AOSP` (per `KEY_AOSP_IME_RAISE_STYLE` "键盘抬高样式": AOSP → 144px, 小米样式 → 0px). Do not revert to full-height unconditional padding.
- **Back button must never synthesize BACK into the app** (微信输入法): `hookNavBarBackButtonDismiss` hooks `NavigationBarView#prepareNavButtons`, `KeyButtonView.setCode(0)`, and adds a click listener calling `InputMethodService.requestHideSelf(0)`. **Resolver trap**: `CompatibleMethodResolver` treats an empty param list as "must be zero-arg", so a name-only lookup of this one-arg method returns null — resolve over `declaredMethods` by name.
- `KEY_AOSP_IME_FORCE_ALL` lifts the customized-keyboard skip so MIUI-customized keyboards are forced onto the AOSP branch; `aospBarActive(context)` drives the hide hook, `addMiuiBottomView` skip, and keyboard raise together. `MiuiImeBottomHooker` makes MIUI's keyboard switcher list every enabled IME (hooks `getSupportIme()`, gated `KEY_AOSP_IME_MIUI_IME_LIST`). `AospImeSystemHooker` (system-server) recomputes `UserData.mImeDrawsNavBar` in `getInputMethodNavButtonFlagsLocked` and extends `isCallingBetweenCustomIME`; it deliberately does **not** override `isCustomizedInputMethod(String)` (that would make every apply-restart drop the keyboard selection via `onHandleForceStop`). The system-server half requires a reboot. `AospImePage.kt` lists `getEnabledInputMethodList()`. `InputMethodModuleManager`/`InputMethodServiceInjector` are in `miui-framework.jar` (the local copy is unversioned — pull a versioned one).

## Xposed Scope

`staticScope=false` in `module.prop`, so it can call `XposedService.requestScope` for runtime-selected input methods; the cost is LSPosed lets the user edit the whole scope list (removing a required entry silently disables its hooks). The scope is declared twice and must stay identical: `app/src/main/res/values/arrays.xml` (`xposed_scope`) and `META-INF/xposed/scope.list`. The system server is declared once, as `system` (current libxposed no longer accepts `android`; `ScopeManager` still treats an `android` entry from an older LSPosed as satisfying `system`. `util/ScopeManager.kt` wraps the 102 scope API; `requestScope` callbacks arrive on a Binder thread, so each result is settled once through an `AtomicBoolean`; `applyManagedDiff` intersects removals with the caller's managed set and subtracts `requiredScope`. `ScopeWarningCard` on Home names removed required scopes. `missingRequiredScope` skips the module's own package (`getScope()` doesn't report self-scope).

## Passkey / Credential Manager Page (密码和账号)

`PasskeyHooker` (feature `unlock_passkey`) unlocks the AOSP credential-manager UI on domestic HyperOS by forcing `miui.os.Build.IS_INTERNATIONAL_BUILD` around the three Settings entry points. `IS_INTERNATIONAL_BUILD` is `public static final` with a non-constant initializer (Settings reads it with `sget-boolean`); ART rejects the reflective write, but the `StaticFieldWriter` Unsafe fallback works. Two fixes: (1) tapping a 其他服务 row did nothing because `launchSettingsActivityIntent` silently returns false when the provider declares no `settingsActivity` — `hookSettingsActivityLaunchFallback` routes GMS to its exported `PasswordManagerActivity` and others to the app-details page; (2) the switches never committed because the OS4 `MaterialSwitch` doesn't wire `CombiPreference`'s commit listener as the `SlidingSwitch` does — `hookCombiPreferenceSwitchCommit` attaches a reflective listener. **SecurityCenter half**: the default-credential writers moved to `...service.CacheService` (R8-renamed `y0`/`x0`), so `hookSecurityCenter` resolves them by shape (resource-read + `putString` invokes) without a class-name dependency.

## Battery Info Debug Page (电池信息)

Settings → Debug → 电池信息 (`ui/page/BatteryInfoPage.kt`, `Route.BatteryInfo`, reader `util/BatteryInfoReader.kt`) — a module-side diagnostics page listing the battery parameters the device exposes. **Two tiers**: the always-readable `BatteryManager`/sticky `ACTION_BATTERY_CHANGED` tier (level/status/voltage/temperature, `charge_counter` from `getIntProperty(CHARGE_COUNTER)`, current from `getIntProperty(CURRENT_NOW)` — µA, sign dropped) is read directly in the module process; the **privileged tier** (`IMiCharge` design capacity, `manufacturing_date`/`first_usage_date`, SOH, `cycle_count`, `authentic`, model/serial) is read inside `com.miui.securitycenter` (runs as `android.uid.system`) by `hook/rules/securitycenter/BatteryInfoHooker`, which pushes a formatted snapshot every 1 s to the module's `BatteryInfoProvider` (`util/BatteryInfoChannel`, authority `com.takekazex.hypertweak.batteryprovider`, exported; `call("set")` is gated to `Process.SYSTEM_UID`). The reader overlays the snapshot on the live tier; unreadable values show 不可用. **Unit rule**: the fuel gauge reports charge/current in µAh/µA (`BatteryInfoChannel.mah`/`ma` divide by 1000 when the magnitude exceeds 100000); dates are `yyyyMMdd` → `yyyy-MM-dd`; charging power ≤ 0 is treated as unavailable. Dual-battery devices (`battery_num=="1"` or any `fg2_*` slot present) show the 副电池 rows; single-battery devices hide them. Auto-refresh 1 s + top-bar Refresh/Copy; a hint appears until the security center has reported. **Row layout**: each row is a left two-line block (Chinese label over the parameter name `key`) with the read value right-aligned, vertically centred — no bilingual-in-one-line, no timestamp line; section titles are single-language. The value font auto-shrinks (9–15sp by length) so long serials fit on one line; **long-press a row copies that row's `label: value`** (`combinedClickable`). **This is module-UI + a SecurityCenter-side hooker (not in `TWEAK_RESTART_SCOPES`)** — the hooker attaches when SecurityCenter starts, so it needs a SecurityCenter restart after the module APK updates. Researched surface: `docs/BATTERY_PARAMETERS_RESEARCH.md`. Verified: `compileDebugKotlin` + `assembleRelease` pass, provider survived in the merged manifest, R8 kept the manifest component, and the formatted snapshot (design capacity 7560 mAh / SOH 97 % / cycle 120 / `2025-09-10`) was read back on-device.

## Module Configuration Storage

Settings live in two independent copies, which is why they "survive uninstall": **module data** (`/data/user/0/.../hypertweak_settings.xml` + `hypertweak_cache.xml`; deleted on uninstall) and the **LSPosed daemon copy** (`modules_config.db` table `module_configs`, keyed by module package with `ON DELETE CASCADE` — LSPosed keeps the module row, so a reinstall silently restores the old config). `Preferences.clearAllSettings()` wipes all three (leaving a bumped `prefs_epoch` row); all getters compare the cache's epoch against the remote and treat a mismatch as "stale → default". A reinstall/clear-data is detected via `first_run_token` (fresh data dir + remote config present → auto-reset once); `last_known_module_activated` marks an ordinary update as not-fresh so upgrades never wipe settings.

## Logging & Diagnostics (日志系统)

`DebugLog.kt` per-process logger → `Preferences.appendDebugLogs`, stored per `debug_log_p_<processTag>` key against a `debug_log_processes` registry (added via `registerDebugLogProcess`); `getDebugLog()` now merges the daemon (remote) store with the module app's local store (so neither shadows the other). Per-process level override: `logLevelFor`/`setLogLevelFor` (`debug_log_level_<tag>`) via `DebugLog.currentThreshold()`; LogsPage drives it in `ProcessLevelsCard`.

**Session header**: each process emits one INFO `Session:` line (device/model/build/hyperos/fingerprint/module v<code>/process) from `DebugLog.sessionHeader()`; the dump interface always prepends a fresh one.

**AI-readable export (do not remove)**: `LogDumpProvider` (authority `com.takekazex.hypertweak.logdump`, exported, read-only) + `util/LogDumpChannel.kt`. `content call --uri content://com.takekazex.hypertweak.logdump --method dump` returns a Bundle with `length`/`preview`/`path` and writes `<filesDir>/logs/latest.txt` + a stamped copy (only into the module's own dirs — never caller-supplied paths); `--method get` returns the text in `data`. Pull via `adb pull <path>`. Exported read-only by design; other `call` methods/gates should stay gated (see `BatteryInfoProvider`).

**Root-cause stability (do not revert)**: `Preferences.getLocalCache()` must never throw — in system_server it runs on the `android` context and would `RuntimeException: No data directory found for package android`, aborting `dispatchSystemServerHookers` (all system hooks). `DebugLog.write()` reads the record toggle defensively (a logging hiccup must never crash a hook callback), and `HookEntry.onSystemServerStarting` wraps dispatch in try/catch → `DebugLog.e` + rethrow.

**Known limitation (2026-08-31, v282, CONFIRMED root cause)**: the module's cross-process debug-log store cannot capture hook-process (system_server/SystemUI) logs. `XposedModule.getRemotePreferences(name)` (used in `HookEntry.initPreferences`, i.e. every hooked target) returns a **READ-ONLY** `RemotePreferences` — `edit().commit()` throws `UnsupportedOperationException: Read only implementation` (verified via a one-shot probe that printed `committed=err:...Read only implementation`, `remote=e1` for every scoped process). Only the module's own process gets a writable handle via `XposedServiceManager.onServiceBind` → `service.getRemotePreferences` (that's why `write{}` settings persist to `module_configs` but `debug_log_p_*` writes from hook processes never do). Binding `XposedService` from hook processes does not help (`XposedServiceHelper` only binds in the module app process). So hook-process logs are only captured by `forwardToXposed` → the LSPosed logger (`/data/adb/lspd/log/verbose_*.log`) and logcat (`adb logcat -s HyperTweak`). The module LogsPage/AI dump (`content://com.takekazex.hypertweak.logdump`) reliably shows only the module-app process's own logs; for hook-process logs read the LSPosed verbose log / logcat via adb root.

## Camera Unlock (相机解锁)

Settings → Tweaks → Camera Unlock (`ui/page/CameraUnlockPage.kt`, `Route.CameraUnlock`). Reverse-engineering notes in the camera caches: `cache/camera-5cd70925b1646cdf/CAMERA_UNLOCK_EVALUATION.md`, `CAMERA_FEATURE_GATES_17ULTRA.md`, and (new baseline) `camera-8f41d7b82453cdeb/OLD_TO_NEW_MAPPING.md` + `GENERIC_RESOLUTION_PLAN.md`. Verified baselines: **OS4.0.0.15.XPMCNXM + camera 6.6.000460.0** and **OS4.0.0.19.XPMCNXM + camera 6.6.000510.0**. On both the whole capability surface funnels through one per-device config object (`com.mi.device.<Device>`).

**REMOVED 2026-08-30 (user request — the switches were useless on the real flagship):** the flagship **config-swap impersonation is GONE** (deleted keys/machinery; the camera always runs its own real config). What stays and is **master-independent**: 街拍 (新街拍 `a3()`/兼容模式), 保留徕卡风格 (`F3/X2`), 超高图片质量 (`CameraUltraQualityHooker`), 徕卡一瞬 (`LegendaryEnter.support()` unlock), 智能构图, 内容凭证, 自适应镜头, 实况运镜 (registry gate `y4()`, K100 effect-table borrow), the independent 伪装 LCC 主题 (`Je/c#V()` + 相机配色 tint-color restore, gated only on `KEY_CAMERA_IMPERSONATE_THEME_LCC`), the shutter-sound bounds guard, and the watermark keep/custom chain (all unconditional). Every kept unlock hooks the REAL config's base Methods (C1143/C1199) or config-independent classes.

**Version-generic resolution (抗版本)**: the camera APK is re-obfuscated every release but only a **subset** of names change per build, and surviving names can be **reused for unrelated classes** (`Ox.g` was the LCC provider on 460, a StateListDrawable helper on 510). All resolution goes through `hook/rules/camera/CameraResolver.kt`: **L1** known dex names (newest first, each validated by method shape), **L2** DexKit probes on surviving plaintext strings (cached; a repurposed name triggers a re-scan), **L3** structural behavioural chains. A failed layer skips only the affected sub-feature with a log line (never throws).

**Regression rails (do not reintroduce)**:
- The watermark keep-model `v()` after-hook MUST return a real `String[]` (`arrayOf<String?>(...)` — an `Any?` third slot infers `Object[]`, whose `String[]` check-cast throws `ClassCastException`, dead-locking the camera).
- Do not gate the watermark keep hooks on the master preference read (before `Preferences` is initialized it returns `false` → no-op → the `S8.d` singleton caches the impersonated strings for the process lifetime — the "17 Ultra" watermark flash). Keep is unconditional.
- Never "re-point" a resolved class by name alone (`Ox.g`/`i5.d` prove the obfuscator reuses names); every resolution carries a method-shape validation. The `S8.d` entry holder ctor must be resolved by its own 2-arg parameter types, not `(Object,Object)`.
- Identity comparison must go through `CameraIdentity.valueEquals` (a `q1()`-style getter returns a **freshly allocated array each call**, so plain `==` never holds). `"M"` is NOT an imaging-identity getter and must never be delegated/identity-compared.
- MasterLive visibility is two-level (registry `y4()` decides whether mode 231 exists; placement is the config `M()[I` array, the sole ordering input of `u2.P`, split at the 254 marker). The injected 红毯 entry must keep `g=false`; the effect-table merge must deep-copy every List field; the per-type video-size substitution (`Kj.D#c()`) requires the mode gate; unknown effect types fall back to 16:9 rather than skipping.
- The shutter-sound bounds guard (`f2.c#a()` clamp) is UNCONDITIONAL (an out-of-range stored `key_shutter_sound` of 4 crashes the camera; do not gate it on a preference read).
- An ezxhooktool `before` callback sees `param.result == null`, so result-dependent logic must run in an `after` hook. `hookCompatStreetSupport()` installs directly from `installHooks()` (never inside a flagship-gated method, or a resolution failure silently skips it). `content credential` resolution is applied only when the switch is already on at attach (static-final write-once; enabling AND disabling need a camera restart).
